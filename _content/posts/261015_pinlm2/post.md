## 1. 알고리즘 선정
영화 추천을 위해 사용자의 정보, 영화의 메타데이터를 활용한다. 사용자의 정보는 연령별 추천같은 곳에 사용하기 위해 수집되고 (20대 여자, 남자 선호 영화), 사용자의 PIN / PASS / SAVED .. 같은 행동 데이터들은 개인 맞춤형으로 추천하기 위해 수집된다.

캡스톤 기간동안 총 3개의 알고리즘을 적용하였다. Rule-based, Suprise-SVD, lightFM 등을 접목해보며 어떤게 우리 프로젝트에 가장 잘 어울리는지 비교 분석해 보았다.

Rule-based 방식은 한 학기 프로젝트였던 캡스톤에서 빠른 개발 진행과 콜드스타트 문제를 방지하기 위해서 임시적으로 적용한 방식이다. 

이후 더 견고한 추천을 위해 ML들을 알아보았다. 영화 추천 알고리즘과 관련하여 검색할때 제일 먼저 나오는 ML 기법들로써 이미 입증된 성능과, 자료들이 많이 있었기에 알고리즘 성능 개선을 위해 사용해 보았다. 

### 1-1 Rule based
밑의 표와 같이 적용가능한 필드에 대하여 음수, 양수값을 주어 장르, 감독, 배우 등의 정보를 기반으로 관련성있는 영화 리스트를 뽑아내느 방식이다.

| 필드 | 점수 |
| :---: | :---: |
| passed | -3 |
| pinned | +4 |
| watched | +6 |
| Neutral | 0 | 
| etc... | .... | 


### 1-2 Suprise SVD
Surprise(Simple Python Recommendation System Engine)는 사용자와 아이템 간의 평점 데이터 기반으로 추천 시스템 쉽게 구현하고 평가할 수 있도록 만든 Python 라이브러리이다. Collaborative Filtering에 특화되어 있으며, SVD, KNN, NMF 등 다양한 추천 알고리즘 제공

| 알고리즘 | 특징 | 한계 | 
| :---: | :---:| :---: |
| KNN | 비슷한 취향의 사용자나, 영화 찾아 추천 | 데이터 커지면 유사도 계산 부담 증가 |
| NMF | 사용자와 영화의 잠재적 특성 학습 | |
| SVD | 사용자와 영화의 잠재 요인을 학습해 선호도 예측 | 신규 사용자 영화에 취약 |

사용자의 좋아요, 싫어요를 수치화 한뒤 영화 취향을 학습하고, 미평가 영화에 대한 선호도를 예측할 수 있어 선정

### 1-3 LightFM
사용자 행동 데이터와 영화 메타데이터 함께 학습해 개인화된 추천 제공하는 하이브리드 추천 라이브러리이다. 좋아요, 싫어요, 저장, 시청 여부 등 다양한 행동 데이터 활용하고, 영화 메타데이터를 결합해 사용자 취향에 맞는 추천 순위를 생성할 수 있어 선정

| 손실 함수 | 특징 | 활용 목적 | 
| :---: | :---:| :---: |
| Logistic | 긍정, 부정 피드백 활용한 학습 | 좋아요, 싫어요 반영 |
| BPR | 사용자가 선호하는 항목의 순위를 높이도록 학습 | 선호 영화 추천 |
| WARP | 추천 목록 상위에 관련성 높은 항목이 오도록 학습 | Top-N 영화 추천 |

WARP 선정 : 좋아요, 저장 등 긍정적인 행동을 보인 영화가 추천 목록 상위에 배치되도록 학습해, Top-N 추천의 정확도를 높이기 위해 선정

## 2. 실험 데이터 선정 - MovieLens 20M
MovieLens 20M : 미국 미네소타 대학의 GroupLens Research 연구팀이 공개한 영화 추천 시스템 연구용 데이터셋 학술 연구와 추천 모델 성능 비교에 활용가능한 데이터셋으로 이루어짐

### 2-1 데이터 정제
해당 데이터셋은 한명의 시청자가 여러개의 영화에 대하여 0 ~ 5 점 리뷰를 남긴 형태이다. 이 데이터셋을 우리의 방식대로 활용하기 위해서는 구간별로 설정하는 작업이 필요했다.

| Action | Rating |
| :---: | :---: |
| Pass | 0.5 ~ 1.5 | 
| Neutral | 2.0 ~ 3.0 |
| Pin | 3.5 ~ 4.5 |
| Saved | 5.0 |

사용자는 크게 4개의 행동패턴을 통해서 영화에 대해 긍정 부정을 나타낸다. pass - 싫어요, neutral - 중립, pin, saved - 좋아요 등으로 구분하였다.

### 2-2 검증 방식
Holdout 방식 평가 : 유저별 전체 리뷰에 대해 시간순 과거 80% 학습(Train), 남은 20% 평가(Test)

| 평가 지표 | 핵심 평가 기준 | 높은 점수 의미 |
| :---: | :---: | :---: |
| NDCG@10 | 추천 순위의 품질 | 선호 영화가 상위에 배치 |
| Recall@10 | 선호 영화의 포함 비율 | 실제 선호 영화를 많이 찾아냄 |
| HitRate@10 | 선호 영화 추천 성공 여부 | 더 많은 사용자에게 유효한 추천 제공 |

### 2-3 핵심 평가 지표
- NDCG@10 (Normalized Discounted Cumulative Gain)
추천 목록에서 사용자가 좋아할 영화를 얼마나 높은 순위에 배치했는가 상위권에 많을수록 높음

    $$
    DCG@10=\sum_{i=1}^{10}\frac{rel_i}{\log_2(i+1)}
    $$


    - relᵢ: i번째 추천 영화의 실제 관련성(이진 평가에서는 선호=1, 비선호=0)
    - DCG : 추천 순위에 따른 가중 점수의 합
    - IDCG : 이상적으로 정렬했을 때 얻을 수 있는 최고 점수

    $$
    NDCG@10=\frac{DCG@10}{IDCG@10}
    $$


- Recall@10 (재현율)
사용자가 실제로 좋아하는 영화 중 상위 10개에 얼마나 많은 영화가 포함되었는가, 추천 순위보다는 선호 영화 얼마나 찾았는가

$$
Recall@10=\frac{\text{상위 10개에 포함된 실제 선호 영화 수}}{\text{사용자의 전체 실제 선호 영화 수}}
$$

- HitRate@10 (적중률)
추천 상위 10개 영화 중 사용자가 실제로 선호하는 영화가 하나라도 포함되었는지 평가 10개중 5개 있으면 50%

## 3. 결과 비교
대부분의 지표에서 lightFM이 더 높은 성능을 냄 hitrate만 보더라도 나쁘지 않은편에 속했다. 초기 빠른개발, 가벼운 환경을 고려했을때 LightFM을 적용하기에 적합하다고 판단

| 평가 지표 | Rule Based | Surprise SVD | LightFM WARP |
| :---: | :---: | :---: |
| NDCG@10 | 1.80% (0.017984) | 4.71% (0.047123) | 9.86% (0.098637) | 
| Recall@10 | 1.23% (0.012287) | 1.87% (0.018692) | 4.61% (0.046149) |
| HitRate@10 | 19.8% (0.198) | 32.6% (0.326) | 54.4% (0.544) |

## 4. 확장 - LightFM + Ontology 
추천 시스템으로써 조금더 개선된 성능으로 확장하는 것이 목표이다. 먼저 현재의 알고리즘을 확장하는 방향으로써 Ontology와의 하이브리드 형태를 고안하였다. 기존의 코드를 재사용하여 조금더 빠른 기간내에 효율적으로 적용시킬 수 있을 것이라 판단하였다.

### 4-1 Ontology 
데이터에 포함된 개념-개념 사이의 관계를 체계적으로 정의하며, 데이터 간 의미적 연결을 표현하는 지식 구조

영화 -> (감독 : 놀란), (장르 : SF), (배우: A), (테마 : 현실, 미래), ... 
즉 <인셉션>을 좋아했다면, 단순히 인셉션과 비슷한 영화가 아닌 SF, 놀란 감독, A 배우, 테마 등을 참조하고 이런것도 좋아할것이라 가능성을 분석한다

### 4-2 문제점 보완
LightFM 단일로 사용하게 된다면 행동 데이터만으로는 사용자가 영화의 어떤 특징을 좋아하는지 충분히 파악하기 어려울수 있을것이라 판단함 그래서 우리는 영화와 사용자 행동에서 의미적 특징을 추출하고, LightFM의 장기 취향 학습과 Ontology 기반 단기 취향 분석을 결합해 추천 후보를 생성하고 순위를 재조정하는 식으로 적용하였다.

장기 데이터 : 최근 1년동안 꾸준히 어떤 장르만 선호한걸 데이터상으로 알수 있음 -> lightFM 사용시 
단기 취향 : 최근 2주정도는 다른 장르 영화에 대한 행동 데이터가 늘어남

| 기존 문제점 | Ontology 도입 목적 | 
| :---: | :---: |
| Sparse Data | 행동 데이터가 부족해도 영화 특징을 활용 |
| Sematic Gap | 장르, 감독, 배우, 테마 등 의미적 관계 반영 | 
| Explainability | 영화가 추천된 이유를 설명한 근거 확보 |



### 4-2 결과
Hybrid 모델은 NDCG@10 18.0%, Recall@10 23.0%, HitRate@22.8% 향상돼 세 지표 모두 개선된 성능을 보였다.
