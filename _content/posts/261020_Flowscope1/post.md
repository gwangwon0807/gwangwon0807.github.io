## 1. 개요

화이트햇스쿨을 시작하고 2달이 흘러 8월이 되었고 팀프로젝트를 진행하게 되었다. 모의해킹 관련 직무애 취업을 원했기에 웹에서 일어날수 있는 사고들을 분석하거나 그런 도구를 만드는 프로젝트를 경험해 보고싶었다.

### 1-1 팀빌딩
디스코드로 이루어 졌으며 "AI-API 플로우 취약점 분석" 라는 주제로 8명의 팀원이 함께 했다. 웹 쪽의 보안사고가 잦아서 인지 유독 인기가 많았던 주제 였고 난이도가 중~상 정도 되는 주제였기에 웹에 대한 이해도와 열심히하려는 의지가 중요할 것이라 판단했기에 팀빌딩에서 부터 열정적인 사람들끼리 모였던것 같다.

우리 말고도 1개의 조가 더 같은 주제에 지원을 했었다. 그렇기 때문에 우리는 더 열심히 할수 있다 라는것을 어필하기위해 각자의 자기소개, 왜 지원했고 어떤식으로 임할건지 간단하게 적은 것을 포함하여 계획서와 함께 멘토님께 보내었다. 다행히 최종적으로 우리팀을 선정해 주셨다.

## 2. 주제 설명

### 2-1 해결 하고자 하는 문제점
화이트햇 스쿨을 하는동안(26.06~26.10 1차교육 ~ 프로젝트 기간) 보안 이슈중 대부분은 API 보안이었던 것 같았다(무신사, 29cm, 강남언니, 위버스, 금융권 등). 이렇게 API 점검에 관한 관심이 증가했다.

AI는 보안 분야에서도 많이 사용되고, 웹 취약점 점검에서도 사용되는 중이다. 여기서 중요한점은 AI 단일 사용으로는 IDOR, BOLA, BFLA등의 객체 권한 문제에 대한 취약점을 찾기 어려운게 현실이다. 그리고 기존의 도구 Burp, fiddler 와 같은 트래픽 수집 도구들은 누구의 트래픽인지, 누구의 객체인지에 대한 지정을 하지 못하기에 가독성 측면에서 떨어진다. 

이렇게 우리는 API 보안을 강화하기 위해 쉽고 빠르게 보안점검을 할 수 있는 도구의 개발을 목표로 하였다. 하지만 어떤식으로 하면 편하게 개발할 수 있을지 고민하기 시작하였다.

### 2-1 API 관찰 방법
우리는 총 3가지로 보았다. 사람 + 스캐너 + LLM 관측을 서로 다르게 설정하여 누가 어디를 탐색했는지 보게 하고, 그걸 시각적인 그래프 형태로 보여준다면 각 소스별로 놓친곳을 볼 수 있을것이라 판단했고, MCP를 적용한다면 LLM도 저 정보를 바탕으로 더 체계적인 탐색을 할 수 있을것이라 생각했다. 

그래프를 생각한 이유로는 IDA가 있었다. 과거에는 Olldbg를 통해 바이너리를 분석하였다. 하지만 수많은 기계어 및 low-level을 통해 분석하는 것은 쉬운일이 아니었다. IDA는 그런 코드들을 그래프 형태로 보여줘 그다음 분기나 흐름을 보기 쉽게 정리해주었다. 그래프로 직관적이게 보여주는것을 우리 도구에도 적용해보고자 생각해게 되었다.

### 2-2 정리
우리는 끊임없는 API보안사고에 대처하기 위한 도구를 개발하기위해 고민하던중 IDA의 그래프 형식을 떠올리게 되었다. 그리고, 그 그래프에는 누가(USER A or B..), 어떤 소스로(사람, 스캐너, LLM), 어느 API(endpoint), 어떤 객체에 접근했는지를 표현해서 사람이 놓친곳이 있는지, 혹은 MCP를 적용해 LLM이 놓친곳이 있는지 알게하여 더욱 쉽게 취약점을 분석하고자 하였다.

## 3. 모임 방식
온라인, 오프라인 둘다 진행하였다. 매주 멘토님께서 공간을 마련해 주셨고 일요일 15시 마다 모여 5시간정도 회의를 진행하였다. 지방에 사는 사람들은 격주에 한번씩은 참가하려고 노력했다. 오프라인에 참여를 못하더라도 온라인으로는 무조건 참여하는 식으로 진행하였다.
