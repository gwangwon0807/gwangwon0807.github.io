## 1. 팀 빌딩
평소에 공모전 같은 활동에 같이 참여하던 학과 친구들과 캡스톤을 진행하게됨, 전부 개발 경험이 있었고 잘하는 부분이 다 따로 정해져 있었다. 총 4명에서 작업을 하였고 프론트 2명과, 백엔드 3명 (1명이 양쪽 다 붙음)으로 진행하였다.

## 2. 역할 분담
각자 완성도 있는 프로젝트를 위해 자신의 강점을 살린 파트를 담당하였다. 나의 경우는 백엔드를 담당하였고, 초반에 아키텍쳐 설계, API 명세 등을 담당하여 빠르고 규칙적인 개발을 할수 있도록 유도하였다.

## 3. 힘들었던 상황 및 극복

### 3-1 맨처음 주제는 음악 추천프로그램
주제를 선정하기 위해 여러 후보들을 선정 해보았고 이후에 스포티 파이라는 음악 스트리밍 서비스의 API를 이용해 사용자의 기분, 현재 날씨 등에 따라서 그에 맞는 음악을 추천해주는 것을 목표로 프로젝트를 진행하려 했다. 하지만 스포티파이의 API 중단 상황이 1달 넘게 지속 되었다. 

우리가 생각했던 타임라인이 많이 꼬여버렸고, 무작정 기다리는것보다. 다른 아이디어를 찾기로 합의하였다. 이후에 독일에 있던 나는, 여자친구와 영화를 보던중에 영화 추천 서비스를 조금더 편하게 만들어보면 어떨까 얘기가 나오게 되었다. 핀터레스트를 보면 자신이 핀한 목록과 관련된게 계속해서 나온다. 그리고 틴더 처럼 스와이프 기능을 접목시키면 훨씬 빠르고 정확하게 사용자의 취향에 맞는 영화를 추천할 수 있을것이라 생각했고 이 아이디어가 채택되어 프로젝트를 진행하게 되었다.

아이디어를 제안했던게 나여서 더욱 열심히 사전조사를 진행하였다. 어떤 API를 쓰면되는지, 어떤식의 UI/UX를 적용시키는게 좋을지 수차례 고민하며 목업 개발등을 진행하며 팀원들에게 더욱더 내 아이디어를 선명하게 나타내 주며 프로젝트가 일관성 있는 방향으로 나아가게끔 유도했다. 아이디어 자체도 괜찮다고 판단 했겠지만 외국에 있는데도 더 열심히 준비하는 열정에 팀원들이 더 믿어주었던 것 같았다. 

### 3-2 지나친 API 의존성
아키텍쳐를 통해 우리는 유튜브, TMDB API에 굉장히 많이 의존하는 중이다. 일단 먼저 유튜브의 경우는 FrontEnd에서 직접 링크를 통해 보여주는 형식으로 구현했기 때문에 법적 제한이 없다. 다운받아서 보여주는것만 아니면 괜찮다고 한다.TMDB의 경우 모든 API를 무료로 사용할수 있게 명시해두었다. 하지만 상업 목적으로 사용하게 될경우 일정 구독료를 지불해야 한다. 다른 API들도 찾아봤지만 우리가 원하는 것들을 제공해 주는게 이 2 플랫폼이 유일했기에 채택하게 되었다.

그래서 우리는 우선 무료 배포및 운영을 목표를 하게 되었고 어느정도 사용자 수가 많아지고 만약 수익 목표로 확장하고자 한다면 구독 및 자체 데이터 확보 하는 방향으로 진행하기로 계획했다.

### 3-3 소통문제로 다툼
이거는 어떤 프로젝트를 하든 발생하는 상황일 수 밖에 없다. 우리는 평소에 정보를 공유하기 위해 노션을 활용하기로 정하였다. 그래서 알고리즘 부분에서 각자 파트를 나누어 조사한것들을 정리하자고 제안하였다. 이렇게 한 이유는 조금 더 빠른 시일내에 양질의 자료들을 수집하기 위해서였다. 그렇게 정리된 내용을 바탕으로 도메인을 쌓으면 회의를 진행할때에도 원활하게 진행 할 수 있을 것이라 판단했다. 이 과정에서 한 팀원이 카톡으로만 내용을 보내고 노션에 정리하지 않길래 정리를 부탁한다고 반복하여 요청하였지만 오히려 짜증을 내며 어떤식의 정리를 원하는지 나에게 요구하는것 이었다. 물론 반복적으로 같은말을 하다보면 불편하게 느낄수 있을것 같다 생각하지만 그래도 정한 규칙이기 때문에 내 의사를 정확히 표현하였고 무사히 진행될 수 있었다. 이후에 내가 행했던 점을 되돌아보며 불편했을 부분에 대해 먼저 사과를 했고 이어서 팀원도 자신의 잘못을 인정하며 좋게 마무리 지을 수 있었다. 다행히 큰 흔들림 없이 작은 해프닝으로 끝났고 성공적으로 마무리할 수 있었다.

## 4 보안적인 고민
나는 물론 컴퓨터공학을 전공하지만, 정보보안인으로써의 꿈을 꾸고 살아가기 때문에 어떤 부분이 취약한지 생각하며 개발하려 노력한다. 당연히 MVP만 만드는데에 있어서는 복잡한 로직이 필요하지는 않다. 하지만 캡스톤 프로젝트이고 추후 배포까지 생각한다면 초반에 기반을 다져 놓는게 좋을 것이라 판단하여 담당을 자처하였다. 

### 4-1 Token
실제로 웹 해킹이나, 모의해킹 등의 작업을 수행할때 JWT같은 인증 부분에 대해서 중요하다는건 많이 들었다. 하지만 정작 서버에서 어떻게 생성하며 어떻게 인증하는지 직접 구현해보진 않았다. 물론, CTF등을 풀다보면 코드를 많이 접하면서 함수, 라이브러리 등을 볼 수 있었다. 그래서 더욱 쉽게 구현할 수 있었고 이후 모든 API에 토큰 인증을 접목시키는 작업을 진행할 수 있었다. 

### 4-2 이메일 인증
회원가입, 비밀번호 찾기 부분에 있어서 이메일 인증을 접목시키는 것을 제안하였다. 카카오, gmail 처럼 OAuth 2.0을 구현하진 않았다. 초기에는 가볍게 구현하였고 실제 배포와 user 확보이후에는 확장하여 개발할 예정이다.

## 5. 성과
한학기 동안 진행하며 현직자와의 인터뷰를 통해 우리가 만든 제품을 보여주며 제작한 PPT를 보여주며 발표를 진행하였다. 실제로 "좋은 아이디어이고 이미 완성도도 있어보이니 창업 대회같은 곳이라도 나가봐라~". "PPT도 엄청 깔끔하게 잘 만드셔서 한학기 동안 하셨다는게 안믿겨지네요" 라고 말씀하시며 좋은 말씀을 해주셨다. 그동안 고생했던게 인정받는 기분이어서 기분이 너무 좋았고 실제로 대회에 나가게 결심하게된 계기가 되었다. 그결과 [2026 강원권 AI-SW 페스티벌(장려상)]을 받을 수 있었다.
